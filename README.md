# Production Exception Tracker

A small Python analytics engine and Streamlit dashboard that summarizes machine production data and flags records whose rejection rate exceeds an alert threshold.

> **All data in this repository is synthetic and fictional.** Thresholds are illustrative, not validated industrial benchmarks.

## Problem and intended users

Production and quality staff need a quick way to see how many units are rejected, which machines or shifts perform worst, and which individual records need a closer look. This project is a learning/portfolio demonstration of that workflow for anyone exploring production-quality analytics.

## Features

- CSV loading with strict validation (required columns, valid dates and numbers, produced > 0, 0 ≤ rejected ≤ produced, downtime ≥ 0).
- Report generation: overall KPIs, machine, shift and monthly summaries, and rejection exceptions.
- Streamlit dashboard with:
  - time period selection (All time, Year to date, Choose a year, Custom range)
  - machine and shift filters
  - configurable rejection alert threshold (default 5%)
  - KPI tiles, monthly production vs. rejects, rejection rate by machine / shift / year charts
  - exceptions table with CSV download
- Automated test suite (pytest, including Streamlit `AppTest` dashboard tests).


```powershell

.venv\Scripts\Activate.ps1
```

## Usage

Run all commands from the repository root.

**Analytics engine** – prints KPIs and writes CSV reports to `reports/` (existing files are overwritten):

```bash
python3 analytics_engine.py
```

**Dashboard:**

```bash
streamlit run dashboard.py
```

**Tests:**

```bash
python3 -m pytest tests -q
```

## Dataset schema

`synthetic_production_2023_2025.csv` – one row per machine per shift per day, 2023-01-01 to 2025-12-31, machines M01–M03, shifts Morning and Evening.

| Column | Meaning |
|---|---|
| `date` | Production date (`YYYY-MM-DD`) |
| `machine_id` | Machine identifier |
| `shift` | Shift name |
| `units_produced` | Units produced; must be > 0 |
| `units_rejected` | Units rejected; 0 ≤ value ≤ `units_produced` |
| `downtime_minutes` | Downtime in minutes; must be ≥ 0 |

The loader adds `rejection_rate_pct` = `units_rejected / units_produced × 100` for each row.

## KPIs and the rejection-rate formula

- **Row rejection rate** = rejected ÷ produced × 100.
- **Aggregate rejection rate** (overall, machine, shift, month, year) = **total rejected ÷ total produced × 100**.

Aggregates use totals, not the average of row percentages, because a simple average gives a 100-unit run the same weight as a 1,000-unit run. Example: 1,000 units with 10 rejects (1%) plus 100 units with 50 rejects (50%) gives 60 ÷ 1,100 = 5.45%, not (1 + 50) ÷ 2 = 25.5%.

Dashboard KPI tiles: units produced, units rejected, overall rejection rate, downtime (minutes), and flagged records.

## Alert threshold

A record is an exception when its rejection rate is **strictly greater than** the threshold; a record exactly at the threshold is not flagged. The default is 5%.

- Dashboard: change **Rejection alert threshold (%)** in the sidebar (0–100, step 0.5; default set by `DEFAULT_ALERT_THRESHOLD` in `dashboard.py`).
- Analytics engine: change `ALERT_THRESHOLD_PCT` in `analytics_engine.py`.

Flagged records are candidates for review, not confirmed root causes.

## Report outputs

`python3 analytics_engine.py` writes to `reports/`:

| File | Purpose |
|---|---|
| `overall_kpis.csv` | Record count, total produced/rejected, overall rejection rate, total downtime |
| `machine_summary.csv` | Totals and rejection rate per machine, worst first |
| `shift_summary.csv` | Totals and rejection rate per shift, worst first |
| `monthly_summary.csv` | Totals and rejection rate per calendar month (`YYYY-MM`) |
| `rejection_exceptions.csv` | Rows above the threshold, worst first |

These are regenerated on demand and are excluded from Git.

## Known limitations

- Data is synthetic; thresholds are illustrative.
- `dashboard.py` contains its own copy of the data-loading/validation logic, separate from `analytics_engine.py`, so the two could drift apart. The dashboard's loader is not unit-tested in isolation.
- Overall KPIs and exceptions are computed inside `analytics_engine.main()`, so tests exercise them through the generated reports.
- Not covered by tests: chart contents, date-preset radio options, and the CSV download button.
- The engine's `ALERT_THRESHOLD_PCT` and the dashboard's `DEFAULT_ALERT_THRESHOLD` are separate constants.
- Records with zero production are rejected as invalid.
- "Year to date" uses the system clock, which with this fixed 2023–2025 dataset shows the latest year available.
- Exceptions are selected on the unrounded rate, while the displayed/exported rate is rounded to 2 decimals.
